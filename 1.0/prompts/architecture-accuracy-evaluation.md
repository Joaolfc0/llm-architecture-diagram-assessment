### Evaluation Criterion — Accuracy

Accuracy is about whether the diagram correctly reflects the architecture described in the text, including components, interactions, and technologies.

In particular, evaluate:

1. **Component Matching**  
   - Do the components in the diagram correspond to the components described in the text, with compatible names, roles, and responsibilities?

2. **Interaction Matching**  
   - Do the interactions in the diagram (calls, messages, data flows) match the interactions described in the text in terms of direction, main participants, and purpose?

3. **Technology Representation**  
   - When specific technologies are mentioned in the description (e.g., databases, message brokers, API gateways, containers), are they represented correctly in the diagram and associated with the correct elements?

---

### Rating Scale (Accuracy)

- **Exemplary Accuracy**: The diagram and description are in strong agreement; no meaningful discrepancies are observed.
- **Acceptable Accuracy**: Mostly aligned, with small mismatches or omissions that can be easily corrected.
- **Insufficient Accuracy**: Noticeable inconsistencies between the diagram and description that can mislead the reader.
- **Deficient Accuracy**: Major contradictions or misrepresentations; the diagram does not reliably reflect the described architecture.
